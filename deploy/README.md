# Installation du premier module de gestion

Le service Bloodline est séparé de `heritage-site.service`, de la base et des secrets du vignoble. Il écoute uniquement sur `127.0.0.1:8082`. La page `gestion.html` est publiée sur GitHub Pages ; le serveur fournit uniquement l'API via ngrok, sous le chemin `/bloodline-api/`. Ne pas exposer directement les ports 8081, 8082 ou 8083 à Internet.

1. Installer ce dépôt dans `/home/dojojo/Documents/bloodline` sans écraser le dossier du vignoble.
2. Créer un environnement Python et installer `requirements-gestion.txt`.
3. Mettre dans `.env` privé : `BLOODLINE_DB_PATH=/home/dojojo/Documents/bloodline/data/bloodline.sqlite3` et `BLOODLINE_PUBLIC_ORIGIN=https://dojojo1.github.io`. Cette valeur est l'origine de la page GitHub Pages autorisée par CORS, pas l'adresse de l'API.
4. Installer Caddy dans `~/.local/bin/caddy`, copier `ngrok-router-user.service` dans `~/.config/systemd/user/` et l'activer. Le fichier `ngrok-router.Caddyfile` écoute seulement sur `127.0.0.1:8083` : `/bloodline-api/*` va vers Bloodline sur 8082 après suppression du préfixe, tout le reste va vers le vignoble sur 8081. La version installée lors de cette mise en place est Caddy 2.11.9, téléchargée depuis la publication officielle avec SHA-256 `5b8cb7faf8726a2028ad96a66e54e6e81e8f361bc6175e5d22bbd997cc5177fb`.
5. Installer `bloodline-gestion-user.service` dans `~/.config/systemd/user/`, activer la persistance de la session avec `loginctl enable-linger dojojo`, puis démarrer le service avec `systemctl --user enable --now bloodline-gestion-user.service`. Tester `/api/health` localement et via l'adresse HTTPS une fois le proxy configuré. Le fichier `bloodline-gestion.service` reste disponible pour une installation système avec droits administrateur.
6. Pour la première installation, créer les deux comptes avec `.venv/bin/python -m scripts.bootstrap_admins Erwan Lucia` depuis le dossier du projet. Deux codes d'activation aléatoires sont écrits dans `~/.config/bloodline/activation-codes.txt` (droits 600). À la première connexion, chacun entre son nom de compte et son code, puis crée son propre mot de passe. Le code est à usage unique. Pour migrer les deux comptes créés avant ce parcours, lancer `.venv/bin/python -m scripts.prepare_first_login` après une sauvegarde : les anciens secrets sont convertis en codes et le fichier privé est renommé. Supprimer le fichier des codes après activation des deux comptes. Ne jamais envoyer un code ou mot de passe dans la conversation.
7. Installer `bloodline-backup.service` et `bloodline-backup.timer` dans `~/.config/systemd/user/`, puis activer le minuteur avec `systemctl --user enable --now bloodline-backup.timer`. Lancer une première sauvegarde avec `systemctl --user start bloodline-backup.service`. Définir `BLOODLINE_BACKUP_DIR` vers un emplacement privé si besoin. Vérifier régulièrement une restauration et copier périodiquement les sauvegardes hors du serveur.

8. Dans la configuration privée ngrok `~/.config/ngrok/ngrok.yml`, conserver l'adresse publique `https://unabashed-tackle-claw.ngrok-free.dev` et pointer son unique upstream vers `http://127.0.0.1:8083`. Conserver une copie privée de l'ancienne configuration. Vérifier le vignoble avec `/api/status` et Bloodline avec `/bloodline-api/api/health` depuis l'extérieur. La page est servie depuis `https://dojojo1.github.io/Bloodline-Tatto/gestion.html` et `gestion.js` utilise le même domaine ngrok avec le préfixe Bloodline. Le tunnel Tailscale n'est plus nécessaire après vérification.

Ne créer aucun compte avec un mot de passe partagé dans un chat. Les jetons de session ne sont jamais placés dans le dépôt ; ils sont conservés par l'onglet du navigateur puis supprimés à la déconnexion.
